# claude-usage-stats

Статистика реальной работы Claude Code по локальным логам сессий: сколько часов агент
работал, сколько сессий молотили одновременно, сколько токенов и правок, и как это
соотносится с коммитами в git.

Отвечает на вопрос «какой объём работы выполняет агент» цифрами, а не ощущениями.

```
 Часов работы агента     Промптов      Написано токенов     Вызовов инструментов
      98,0 ч              1 207            11,53 M                 21 033
```

Ставить и клонировать ничего не нужно — запускается через `npx`. Зависимостей нет,
только стандартная библиотека Node 20+. Данные никуда не отправляются, всё считается
локально.

## Быстрый старт

```bash
# всё одним блоком за прошлую рабочую неделю
npx github:Happiest-d/claude-usage-stats summary --last-week --repo ~/projects/api

# подробная сводка: по дням, моделям, инструментам, проектам
npx github:Happiest-d/claude-usage-stats stats --last-week

# параллелизм: сколько агентов работало одновременно
npx github:Happiest-d/claude-usage-stats concurrency 2026-07-20 2026-07-24

# HTML-дашборд по неделям за июль, с коммитами из своих репозиториев
npx github:Happiest-d/claude-usage-stats report --month 2026-07 \
  --repo ~/projects/api --repo ~/pet/other -o july.html
```

`report` кладёт рядом самодостаточный `dashboard.html` — все графики, данные и стили
внутри одного файла, внешних запросов нет. Открывается локально в браузере.

Чтобы не писать длинную команду каждый раз, поставь глобально:

```bash
npm install -g github:Happiest-d/claude-usage-stats
claude-usage-stats stats --last-week      # или короткое имя: claude-stats
```

## Команды

| Команда | Что делает |
|---|---|
| `summary` | Всё одним блоком: часы работы агента, параллелизм, промпты, токены, инструменты, файлы и коммиты |
| `stats` | Подробная сводка: токены, запросы, инструменты, модели, проекты, разбивка по дням |
| `concurrency` | Параллелизм: агент-часы, календарное время, распределение по числу одновременных сессий, пик |
| `report` | HTML-дашборд по рабочим неделям (пн–пт) |
| `weekly` | Понедельная агрегация в JSON — то, из чего собирается дашборд |
| `git` | Коммиты и строки по тем же неделям в JSON |

Без команды выполняется `stats`.

## Период

Даты в формате `YYYY-MM-DD`, обе включительно; можно позиционно или через `--from` / `--to`.

| Флаг | Что значит |
|---|---|
| `2026-07-06 2026-07-31` | явный диапазон |
| `--last-week` | прошлая рабочая неделя, пн–пт |
| `--this-week` | текущая неделя с понедельника по сегодня |
| `--days N` | последние N дней, включая сегодня |
| `--month [YYYY-MM]` | месяц целиком; без значения — текущий |

## Опции

| Опция | По умолчанию | Зачем |
|---|---|---|
| `--json` | — | JSON вместо текстового отчёта (`summary`, `stats`, `concurrency`) |
| `--repo PATH` | — | Репозиторий для статистики коммитов, можно несколько раз |
| `--email ADDR` | `user.email` репозитория | Email автора коммитов, можно несколько раз |
| `-o, --out FILE` | `dashboard.html` | Куда писать дашборд |
| `--tz ±HH:MM` | системный пояс | Пояс, в котором режутся сутки и недели |
| `--idle N` | `5` | Порог простоя в минутах (см. ниже) |
| `--logs DIR` | `~/.claude/projects` | Каталог логов, если он нестандартный |

То же самое через переменные окружения: `CLAUDE_STATS_TZ`, `CLAUDE_STATS_IDLE_MIN`,
`CLAUDE_CONFIG_DIR` (флаг перебивает переменную).

```bash
claude-usage-stats concurrency --last-week --idle 2   # строже к паузам
```

## Как считаются метрики

**Час работы агента.** Интервал открывается на промпте человека и закрывается ответом со
`stop_reason: end_turn` — то есть моментом, когда агент вернул управление. Ожидание твоего
ввода между ходами работой не считается. Разрывы длиннее порога простоя вырезаются.

**Агент-часы против календарного времени.** Агент-часы — сумма по всем сессиям: две сессии,
работавшие час параллельно, дают два агент-часа. Календарное время — сколько времени
работала хотя бы одна. Их отношение и есть средний параллелизм (`×1,26` — типичное
значение для одного человека с несколькими окнами).

**Параллелизм.** Календарное время раскладывается по числу одновременно работающих
сессий: сколько времени работала ровно одна, ровно две и так далее. Отдельно считается
пик по агентам, где каждый субагент учитывается сам по себе.

**Сессии и субагенты.** Субагенты пишутся в `<сессия>/subagents/` и наследуют `sessionId`
родителя, поэтому в метрике сессий их время схлопнуто с родительским — иначе один веер
субагентов выглядел бы как десяток параллельных окон.

**Токены.** Дедуплицируются по `requestId`: одно API-сообщение попадает в лог несколькими
строками с одинаковым usage, и наивный подсчёт завышает результат примерно вдвое.
«Контекст» в дашборде — это `cache_read + cache_write + input`, то есть весь объём,
который модель прочитала.

**Строки.** Считаются по содержимому `Edit`/`Write`: переписывание одного места
учитывается заново, поэтому цифра всегда выше git-диффа. Для реального результата рядом
показаны коммиты.

**Коммиты.** Отбираются по email автора, а не по имени: один человек часто коммитит под
разными написаниями имени, и подсчёт по имени тихо теряет часть работы. По умолчанию
берётся `user.email` самого репозитория, можно задать явно через `--email`.

## Что в статистику НЕ попадает

- Работа через веб, десктопное приложение и IDE-расширения — считаются только логи CLI.
- Агенты, запущенные в контейнере или на другой машине: они пишут логи в свой HOME.
  Например, headless-бот в Docker с собственным томом под `~/.claude` будет невидим,
  даже если его код лежит в твоём проекте, а хостовый `~/.claude` смонтирован ему
  на чтение. Такие прогоны считай отдельно, изнутри их окружения.
- Всё, что старше ротации логов: Claude Code со временем подчищает `~/.claude/projects`,
  так что за давние периоды данных может просто не быть. Проверить границы:

  ```bash
  ls ~/.claude/projects/*/*.jsonl | head -1
  claude-usage-stats stats 2026-06-01 2026-06-30    # скажет, если записей нет
  ```

## Устройство

```
bin/cli.js            разбор аргументов и выбор команды
src/clock.js          пояс, границы суток и рабочих недель
src/logs.js           разбор логов: чтение (I/O) отдельно, извлечение полей отдельно
src/aggregate.js      один проход по логам, из которого строятся все отчёты
src/metrics.js        чистые функции: интервалы работы, sweep по параллелизму, часы
src/commands/*.js     по файлу на команду
src/table.js          таблицы в рамках для терминала
src/html.js           склейка template.html с данными
src/template.html     вёрстка дашборда, данные подставляются вместо __DATA__
```

Читать логи дорого — около трёх секунд на месяц, — поэтому команды не ходят по файлам
сами: `aggregate` собирает всё за один проход, а команды только раскладывают результат
по-своему. `summary` за счёт этого стоит столько же, сколько `stats`, хотя показывает
данные обеих команд сразу.

Формат логов не документирован публично и может поменяться между версиями Claude Code.
Если после обновления цифры поедут — смотреть надо в `src/logs.js`: там всё, что знает
про структуру записей (`isHumanPrompt`, `isTurnEnd`, `usageOf`, `toolUses`).
Остальные модули работают уже с разобранными данными.

Одна тонкость про воспроизводимость: при `resume` часть записей копируется в новую
сессию с прежним `uuid`, но новым `sessionId`. Дедуп оставляет ту копию, что встретилась
раньше, поэтому список файлов всегда сортируется — иначе агент-часы гуляли бы в пределах
десятых долей процента от запуска к запуску.
